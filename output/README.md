# `output/` — screening artefacts, not the ledger

Everything in this directory is **research output**: the daily run of the screen, written out
so the funnel can be inspected and reproduced. **None of it is a holding.**

The book itself lives in [`data/ledger/`](../data/ledger/):

| File | What it is |
|---|---|
| `data/ledger/constituents.csv` | **The holdings.** One row per constituent, with entry date, entry price and entry weight. Reviewed twice a year (January and July, METHODOLOGY §7.1); never rebalanced after entry (§7.3). |
| `data/ledger/index_level.csv` | The daily index level. Append-only, one row per trading day. |

## Files here

| File | What it is |
|---|---|
| `funnel_YYYY-MM-DD.csv` | How many names survived each screening layer that day. |
| `candidates_YYYY-MM-DD.csv` | The full ranking of L4 survivors after dual-class de-duplication. |
| `book1_index_YYYY-MM-DD.csv` | **A daily ranking snapshot, not the book.** See the note below. |
| `index_chart.svg` | Generated by `src/render_chart.py` from `index_level.csv`; embedded by both READMEs. |

## A note on `book1_index_*.csv`

The name reads like "the constituents of Book One". It is not. It is what the screen would
pick **if the book were opened that day**, recomputed from scratch every trading day. The
holdings do not follow it.

The two diverge immediately and by design. Between 2026-07-20 and 2026-07-27 the snapshot
swapped four names in and out (VRSK in then out, MCO in then out, BR out then back, GRMN
back in) while the book did not move at all. That churn is noise, not signal: the candidate
pool is small and the scores at the bottom of the ranking sit within ~0.004 of each other, so
a day's price move reorders them. Rule §7.3 — never rebalance after entry — exists precisely
to keep that noise out of the book.

**If you want to know what is held, read `data/ledger/constituents.csv`.** Nothing in this
directory answers that question.

The filename is kept as-is: these files are published daily and archived externally, and
renaming past artefacts would break paths that have already been recorded elsewhere. Fixing
the name is a forward-only change, to be made in its own commit.
